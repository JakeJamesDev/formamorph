# Art provenance: bundled-world images that predate the expansion

Where every image that still ships in the bundled worlds came from, when the bundled worlds
expansion's art tickets did not make it. The question is whether all of it is generated content
and not something found online.

- **Read at:** `main` @ `d4fde35be` (2026-10-26), after ticket 15 (Valentines art) landed in `59a057379`. Ticket 16 (Veilwood art) was still `in-progress`, so Veilwood can change after this read.
- **Scope:** `src/defaultworlds/*.json`, every `data:` image, including thumbnails and Map Backgrounds.
- **Nothing here edits a world file.**

▶ **Resume here:** all checks are done, including the reverse image search (2026-10-27). What is left is the user's call on the images under Open items.

- **19 of the 22 old images** came from the original upstream project. The upstream author added them in its first commit, `e608a3daa` ("first commit v1.1.14", Fierylion, 2025-04-06). That includes all seven animated Veilwood portraits.
- **No old image is proven to be found online.** No old image is proven generated by the upstream author either, except the Veilwood cover, which carries a signed DALL·E content credential.
- **A reverse image search found no outside copy of any of the 18 unproven images.** Google Lens and Bing both ran on each. The only exact matches are Neonspire on Formamorph's own sites.

### Embedded metadata

The GIF format has no standard field for a generator, and none of the seven names a tool.

| GIF block | Found in |
|---|---|
| `NETSCAPE2.0` (loop forever) | all seven |
| Comment: `GIF edited with https://ezgif.com/resize` | Shadow Raptor, Dread Crawler |
| Anything else (XMP, generator comment) | none |

The ezgif comment means those two were resized on ezgif.com, which explains their 300×300 size against the others' 256×256. It says nothing about how the frames were made.

### How they were made: what the files show

- **Each portrait is a turntable.** One object turns a full circle around its vertical axis over the loop. The mushrooms show every side. The two creatures turn from front to side to back.
- **Every portrait uses the same studio setup.** The five 256×256 portraits have a flat, opaque `#333333` background on every frame. The two resized ones are `#303030` to `#323232`, which is that same gray after resizing and requantizing.
- **One pipeline made all seven.** Same background, same 100 ms frame time, same 40-frame length on every portrait whose data is whole.
- **The look matches a generated 3D model rendered as a turntable.** Soft procedural textures, no rig or pose change while turning, and a plain gray preview background. Image-to-3D and text-to-3D services export previews like this.

⚠️ **UNVERIFIED:** which tool made them. Nothing in the files, in the upstream commits, or in the upstream README and notes names one. The commit messages here only say the art was kept.

### Verdict

🟡 **Likely generated** (style and lineage only), for all seven. The evidence is consistent, but no file proves the tool. The reverse image search found no page with any of the seven, on Google Lens or Bing, so no stock or online source turned up. Bing's visual matches were similar-looking 3D models on Sketchfab and TurboSquid, none of them the same object.

Contact sheets (untracked): `.scratch/art-provenance/veil-frames.png` (six frames per portrait) and `.scratch/art-provenance/veil-orbit.png` (ten-step orbits of Cerulean Vex and Dread Crawler).

### 🟡 Upstream art without metadata (rows 1, 6 to 16)

What the files show:

- **No generator metadata survives.** The JPEGs hold only a JFIF header. Their quantization tables are the standard libjpeg quality-75 tables, so some tool re-saved them and stripped any EXIF.
- **The upstream world file mislabeled them.** Rows 6 to 9 and 16 were JPEG bytes in `data:image/png` URIs. The upstream editor stored uploads as-is through `readAsDataURL`, so the source files were JPEGs with a `.png` name. `779082681` relabeled one of them.
- **The Sugarscape sprites (rows 11 to 15) are screen snips.** Each upstream PNG had only `sRGB`, `gAMA` 45455 and `pHYs` 3779 px/m (96 DPI). That set comes from Windows screen-capture and Paint-style tools. Their odd sizes (707×604, 311×300…) fit a crop around one subject. A snip loses any metadata the original had.
- **Style.** All of them read as generated art: anime-style SDXL-type scenes (Magiterra Nova, the Valentines hallway), a soft 3D toy-render (drone thumbnail, Sugarscape sprites), and photoreal candy terrain (Sundaelora, Strawberrycream Shores). Sizes 1536×896 and 1360×768 are common generator output sizes. None of this is proof.
- **Upstream records nothing about art.** The upstream README, `src/README.md` and `src/notes/*` at `e608a3daa` name no art tool or source. Upstream's later commits never touched a world file.

## Reproduce

Scripts and outputs are untracked in `.scratch/art-provenance/`:

- [inventory.mjs](../../../.scratch/art-provenance/inventory.mjs) lists every image at a revision: `node .scratch/art-provenance/inventory.mjs <rev|WORKTREE> <out.json>`. Set `DUMP=<dir>` to write the decoded files.
- [meta.mjs](../../../.scratch/art-provenance/meta.mjs) dumps C2PA, PNG text, GIF extension and JPEG header blocks.
- [gifdec.mjs](../../../.scratch/art-provenance/gifdec.mjs) decodes a GIF frame by frame, including truncated ones that libvips rejects, and compares it to a WebP.
- [pixcmp.mjs](../../../.scratch/art-provenance/pixcmp.mjs) and [near.mjs](../../../.scratch/art-provenance/near.mjs) compare pixels exactly or after a resize.
