# How multi-endpoint clients handle reasoning

Research date: 2026-10-14. Primary sources only: each project's source on GitHub, plus its official docs.
Each app section names the branch and commit it was read at. Links point at that commit.

## 🧭 Key findings

- **Most clients put the thinking budget *inside* `max_tokens`.** They take a fraction of `max_tokens`, set a floor of 1024, and clamp the result to `max_tokens - 1` (or 80–95%). SillyTavern, Cline, Roo Code, LibreChat, LobeChat, Cherry Studio, and KoboldCpp all work this way.
- **Only the Vercel AI SDK *adds* the budget:** `max_tokens = maxOutputTokens + thinkingBudget`, then clamps to the model's limit. Jan relies on this behavior for Anthropic.
- **Effort-to-budget ratios are similar everywhere:** low ≈ 0.1–0.25, medium ≈ 0.25–0.5, high ≈ 0.5–0.8, max ≈ 0.95–1.0, applied to the output cap. Jan is the exception: it applies the ratios to the *context window*.
- **The newer clients classify endpoints by control shape.** Cline uses `effort` / `budget_tokens` / `toggle`. Cherry Studio uses `off` / `auto` / `effort` modes, each with a budget policy. LibreChat uses `reasoningFormat` = disabled / `reasoning_effort` / `reasoning_object`.
- **Clients now send an explicit "off".** Cline sends `reasoning_effort: "none"` when reasoning is off, so models that reason by default stop thinking. llama.cpp's server honors `reasoning_effort: "none"`.
- **When the model thinks but never answers, no client continues the thought.** They retry (Cline, Roo Code), error out (SillyTavern quiet calls, Cline), or save and show the thought (SillyTavern chat). SillyTavern's docs tell users to raise Max Response Length.
- **The real fix for a local runaway thought is server-side budget forcing.** KoboldCpp and llama.cpp both stop the thought at the budget. They inject a message plus the end-of-think tag, and the model then answers. llama.cpp takes the budget per request as `reasoning_budget_tokens` or `thinking_budget_tokens`.

- **Knobs.** The "Request model reasoning" checkbox is `show_thoughts`, default `true` ([openai.js:394](https://github.com/SillyTavern/SillyTavern/blob/06bde93/public/scripts/openai.js#L394), [:507](https://github.com/SillyTavern/SillyTavern/blob/06bde93/public/scripts/openai.js#L507)). Reasoning Effort is a dropdown: auto/min/low/medium/high/max, default `auto` ([index.html:2164-2170](https://github.com/SillyTavern/SillyTavern/blob/06bde93/public/index.html#L2164), [openai.js:239-246](https://github.com/SillyTavern/SillyTavern/blob/06bde93/public/scripts/openai.js#L239), [:508](https://github.com/SillyTavern/SillyTavern/blob/06bde93/public/scripts/openai.js#L508)). The default Max Response Length is 300 ([openai.js:423](https://github.com/SillyTavern/SillyTavern/blob/06bde93/public/scripts/openai.js#L423)).
- **Effort → literal.** `getReasoningEffort` handles OpenAI-style sources ([openai.js:2545-2663](https://github.com/SillyTavern/SillyTavern/blob/06bde93/public/scripts/openai.js#L2545)). `auto` sends nothing. `min` becomes `'none'` on OpenRouter when reasoning display is off, `minimal` or `none` on GPT-5.x, and `low` elsewhere. `max` becomes `high`, except for model-specific cases. It also checks the model list's `supported_reasoning_efforts` metadata ([:2653-2657](https://github.com/SillyTavern/SillyTavern/blob/06bde93/public/scripts/openai.js#L2653)).
- **Effort → budget, inside `max_tokens`.** `calculateClaudeBudgetTokens` uses: min 1024; low ⌊0.1·max⌋, medium 0.25, high 0.5, max 0.95; floor 1024; capped at 21333 when not streaming ([prompt-converters.js:1124-1172](https://github.com/SillyTavern/SillyTavern/blob/06bde93/src/prompt-converters.js#L1124)). Adaptive Claude models get an effort string instead. The Gemini Flash budget uses the same ratios with max = 1.0, capped at 24576 ([:1182-1206](https://github.com/SillyTavern/SillyTavern/blob/06bde93/src/prompt-converters.js#L1182)). If `max_tokens ≤ 1024`, the server adds 1024 to `max_tokens` and logs "Increasing response length" ([chat-completions.js:375-381](https://github.com/SillyTavern/SillyTavern/blob/06bde93/src/endpoints/backends/chat-completions.js#L375)).
- **The docs lag the code.** The docs say Low is 15% and that max response is raised to 2048 ([docs: Reasoning](https://docs.sillytavern.app/usage/prompts/reasoning/)). The code says 0.1, and +1024.
- **Capability.** A hard-coded `OPENAI_REASONING_EFFORT_MODELS` list decides which models get `reasoning_effort` ([constants.js:461](https://github.com/SillyTavern/SillyTavern/blob/06bde93/src/constants.js#L461)). On the Custom source, it is sent only for those models or for `koboldcpp/*` ([chat-completions.js:2600-2606](https://github.com/SillyTavern/SillyTavern/blob/06bde93/src/endpoints/backends/chat-completions.js#L2600)). Anything else goes in through the user's YAML "include body" ([:2409](https://github.com/SillyTavern/SillyTavern/blob/06bde93/src/endpoints/backends/chat-completions.js#L2409)).
- **No answer.** The chat path saves the reply with its `reasoning`, even when the text is empty ([script.js:5486-5535](https://github.com/SillyTavern/SillyTavern/blob/06bde93/public/script.js#L5486)). `generateRaw` (quiet/background calls) throws `No message generated` on empty text ([script.js:4146-4148](https://github.com/SillyTavern/SillyTavern/blob/06bde93/public/script.js#L4146)). The docs say empty or incomplete replies mean Max Response Length should be raised, and that continuing a reasoning-only message lets the model finish the thought first ([docs](https://docs.sillytavern.app/usage/prompts/reasoning/)).
- **Local.** Auto-Parse defaults to off, with prefix `<think>` and suffix `</think>` ([power-user.js:274-284](https://github.com/SillyTavern/SillyTavern/blob/06bde93/public/scripts/power-user.js#L274)). I found no `enable_thinking`, `chat_template_kwargs`, or `reasoning_budget` code anywhere in `public/scripts` or `src`.
