# 03: Storyboard

Status: ready-for-human
Blocked by: 01
Recommended model: Claude Opus 5.5 (`claude-opus-5-5`)
Reasoning effort: high

Rationale: product judgment: choosing which features sell, their order and the copy; the user rules on the result.

Parent: [Trailer spec](../spec.md)

## What to build

A storyboard document in the spec folder plans both cuts before any scene is built.

- A feature list drawn from the changelog and the landing page, ranked by what sells the app. The user cuts it down.
- A shot list for the wide cut: scene type, copy, which world and screen each frame comes from, duration in frames, transition. Target under 90 seconds.
- The first 6 seconds work as a silent loop (microtrailer).
- The tall cut's shot list, derived from the wide one: which shots drop, which crop, which stack.
- Every line of copy follows the app's copy rules (STE, positive contract, Formamorph terms) and is ready for the copy sweep.
- The storyboard adds its shots to the capture list in ticket 02's format, so capture work can start as soon as the storyboard is approved.

The user approves the storyboard in this session; rulings fold into the spec.

## Acceptance criteria

- [ ] The storyboard names every scene of the wide cut with copy, source frame, duration and transition.
- [ ] The tall cut shot list is derived from the wide one.
- [ ] The first 6 seconds are planned as a standalone loop.
- [ ] The user has approved the storyboard and the spec records the rulings.
