Tile Drag: Cell Sim vs Push / Swap PROTOTYPE — throwaway

This page imports the app's real simulation, so it needs the dev server: npm run dev -- --port 5180, then open http://localhost:5180/docs-internal/specs/tile-drag-push-swap/prototype.html. Opened from a plain file, nothing below will respond.

The pivot: today a tile dodges the moment the carried footprint sweeps it, so the board reflows under the hand on every cell of travel. The new design mirrors an Android home screen. Nothing moves until the hand has rested on a spot. A rest on the same row or the same column as the pickup pushes the tiles between the two spots back toward the hole, far enough to clear. A rest on a different row and column swaps the tile under the hand into the hole. Every preview is computed from the pre-drag board, so leaving a spot undoes what it did. Folder vs move: the pointer picks the target tile. A line runs from the pickup's center to the target's center; a plane perpendicular to it cuts the target so the far slice covers a set share of it. Pointer in the far slice = move; anywhere else on the target = folder (shown as a highlight, not a real folder). Left board is what ships; right board is the proposal. Same seed, same gesture. Double-click a tile to cycle its size.

Esc cancels a drag.

Current — Cell Simulation (shipped)

The board runs the shipped sim through the whole gesture. Every cell the footprint sweeps dodges behind the trailing edge at once; a bigger tile hops once half its cells are swept. The carried tile's hole is the only landing signal. Grouping: rest on a tile the drag cannot move and it rings after a beat; release folds the carried tile into it.

New — Push / Swap (Android home)

The outline follows the hand and turns gray while it waits for the rest. After the rest: same row or column pushes every tile between pickup and target toward the hole, by one carried span, or until the target is clear (radio above). Different row and column swaps the tiles under the target into the hole, shape and offset intact. A push or swap that would land off the board or on a bystander is blocked (red); release there snaps the tile home. An open spot moves nothing else. Folder: the pointer names the target and the footprint snaps to it (equal sizes take its cells; a bigger carried tile must contain it; a smaller one sits inside it), biased toward the pickup home and skipping placements that would block. Past the plane is a move, short of it rests into a folder ring.
